## First: `#10ns` won't compile

Unit-suffixed delays are **SystemVerilog**. In a `.v` file Vivado runs `xvlog` without `-sv`, so `#10ns` is a syntax error. The unit has to come from `` `timescale ``, which is why that directive mattered.

So the unit is set once at the top, and the number is now named:

```verilog
`timescale 1ns / 1ps        // one time unit = 1 ns

localparam STEP_NS = 10;    // ...so #STEP_NS waits exactly 10 ns
```

## I also fixed a readability trap in your original

Your delays were dangling at the end of each line:

```verilog
A=0;B=0;#10        // <-- this #10 belongs to the NEXT line's statement
A=0;B=1;#10
```

Verilog parses that as `#10 A=0;` — *wait 10, then assign*. It produced the right waveform by luck of ordering, but it reads backwards, and the moment you add a line in the middle it bites. Now each line applies its vector and then holds:

```verilog
A=0;B=0; #STEP_NS;                     //  0 ns .. 10 ns
A=0;B=1; #STEP_NS;                     // 10 ns .. 20 ns
A=1;B=0; #STEP_NS;                     // 20 ns .. 30 ns
A=1;B=1; #STEP_NS;                     // 30 ns .. 40 ns
```

Plus `$timeformat(-9, 0, " ns", 6);` so the **console** prints ns too, not just the waveform.
