### 1. `vritra_fc/Sensors.h` / `Sensors.cpp` — sensor hub

**Architecture.** One `SensorHub` singleton (`Sensors`) owns the entire I2C0 bus (SDA=18, SCL=19, 100 kHz — 400 kHz was tested and *breaks the ICM-20948* on this exact harness: address ACKs but every register read returns 0xFF) and both GNSS UART candidates. `begin()` arms a non‑blocking staged state machine (`InitStage` enum: `IS_RECOVER→IS_WIRE→IS_BMP_PROBE→...→IS_GNSS_CFG→IS_DONE`); `service()` must be pumped every loop and never calls `delay()` except the 90 µs of manual clock pulses in `busRecover()`. No vendor sensor library is used anywhere — every register is written explicitly (named against datasheet fields) and validated by reading back a plausible value, because "a register write ACKing proves the bus transaction worked, not that the device behaviour is correct."

**BMP585 barometer** (7Semi breakout). Addr `0x47` (SDO high) primary, `0x46` fallback; `CHIP_ID` reg `0x01` must read `0x51`. Registers: `BMP_TEMP_XLSB=0x1D` (6‑byte burst T[3]+P[3]), `DSP_IIR=0x31` (forced to `0x00` — on‑chip IIR OFF; the 7Semi vendor library left this at coefficient 127 ≈12 s time constant, causing "altitude frozen"), `OSR_CONFIG=0x36` = `0x40|(0x04&lt;&lt;3)|0x01` (press_en, Px16, Tx2), `ODR_CONFIG=0x37` code `0x14` = 25.005 Hz. **`DSP_CONFIG` (0x30) is deliberately never written** — it holds pressure/temp compensation enables, not a filter, and zeroing it silently takes output out of range while every write still ACKs. Init sequence issues a soft reset (`CMD=0x7E` ← `0xB6`), waits, sets standby ODR, then configures IIR/OSR/normal‑ODR, waits ~30 ms for first conversion, then verifies a physically plausible pressure (50000–110000 Pa) before accepting. Conditioning: median‑of‑5 (`BARO_MEDIAN_N=5`) then a glitch gate at `BARO_GLITCH_PA=50` Pa (~13× the measured 3.8 Pa noise floor) with `BARO_SMOOTH_ALPHA=0.35` single‑pole smoothing; a rejected glitch instead exponentially re‑acquires at 0.05. ### 6. `vritra_fc/vritra_fc.ino` — FSM and main loop

### 7. `vritra_gs/vritra_gs.ino` — ESP32 gateway

### 8. `Base36.h` (fc vs gs)

**Byte-identical** (verified via diff — no drift). Encodes every numeric field as `llround(value*div)` in base-36 (0-9 then A-Z), chosen because decimal ASCII can't fit all mandated §6.3.i fields into the 99-byte SF10 airtime ceiling at 1 Hz, while base-36 (5.17 bits/char vs 3.32) does with margin. Uses `double`/`llround` (not `float`/`lroundf`) because lat/lon at 1e6 scale exceed a 24-bit float mantissa's exact-integer range. `B36_CORE[17]` table (scales for TIME_S..FLAGS), `B36_OPT[16]` rotating table + `B36_OPT_MAP[16]` (destination SCHEMA index per frame), `B36_ATT={10,1}`, `B36_QUAT={1000,3}`. `b36SchemaSum()` (FNV-1a hash folding both tables + frame count) is printed by both boards at boot specifically so a drift between the two copies is caught immediately rather than silently corrupting every decoded field.

### 9. `docs/IMU_AXIS_CALIBRATION_2026-08-06.md`
